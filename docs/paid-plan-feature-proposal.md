# 有料プラン機能案

作成日：2026年6月2日

## 目的

SubTrack の有料プランは、サブスクリプションを多く管理する利用者が、次回支払い、更新忘れ、支出の偏りをより確実に把握できる状態を提供する。

無料プランは、少数のサブスクリプションを記録して価値を確認できる入口にする。
Premium は、管理件数が増えた利用者、通知を細かく使いたい利用者、記録を外部に残したい利用者向けの拡張枠にする。

## 現状の前提

現在の販売条件は、Premium 月額300円、年額3,000円、Premium 買い切り6,000円で整理されている。
Premium のサブスクリプションには、初回アップグレード時に7日間の無料お試しが適用される場合がある。

実装上は、Premium の契約状態または買い切り権限が有効な利用者を有料利用者として扱う。
無料利用者はサブスクリプションを最大5件まで登録できる。
CSV エクスポートは Premium 向けに制限されている。

画面文言では、登録件数、カテゴリー件数、支払い方法件数、広告非表示、画像登録、個別通知設定、CSV エクスポートが Premium 機能として案内されている。
ただし、現時点で実装済みの制御と完全に一致していない可能性がある。
公開前に、実装済みの機能と画面上の表現を揃える必要がある。

## プラン設計の方針

無料プランでは、サブスクリプション管理の基本価値を隠さない。
登録、一覧、カレンダー、基本分析、基本通知は、少数利用なら自然に試せる状態にする。

Premium では、管理対象が増えたときに必要になる機能を提供する。
上限解除、詳細通知、深い分析、エクスポート、入力補助、見た目のカスタマイズを中心にする。

買い切りは、サブスクリプション管理アプリにさらに月額課金したくない利用者の受け皿にする。
機能内容は Premium と同じにし、料金体系だけを分ける。

## 推奨する機能構成

| 項目                     | 無料プラン                         | Premium / 買い切り                                           |
| ------------------------ | ---------------------------------- | ------------------------------------------------------------ |
| サブスクリプション登録数 | 最大5件                            | 無制限                                                       |
| 一覧表示                 | 利用可能                           | 利用可能                                                     |
| カレンダー表示           | 利用可能                           | 利用可能                                                     |
| 基本分析                 | 月額換算、年額換算、サービス別内訳 | 基本分析に加えて、推移、予測、重い支払い月の検出             |
| 通知                     | 基本の支払い日前通知               | 個別通知、複数通知、通知時刻、無料お試し終了、解約期限の通知 |
| エクスポート             | なし                               | CSV、将来的に PDF / JSON                                     |
| 入力補助                 | 手動登録                           | サービス候補、ロゴ、色、支払い周期の候補                     |
| カスタマイズ             | 標準テーマ                         | 追加テーマ、アイコン、表示密度                               |
| サポート                 | 通常                               | 優先対応、データ移行相談                                     |

## 優先順位

### P0: 現在の有料価値を明確にする

まず、すでに価値として説明しやすい機能を Premium の中核にする。

1. サブスクリプション登録数の上限解除
2. CSV エクスポート
3. Premium / 買い切りの状態表示
4. 無料枠の上限到達時の案内
5. 設定画面、FAQ、オンボーディング、利用規約の表現統一

この段階では、実装済みでない機能を主要訴求にしない。
特に、カテゴリー件数、支払い方法件数、画像登録、広告非表示は、実装状況を確認してから表現する。

### P1: Premium の継続利用理由を作る

次に、利用者が継続的に使うほど価値が増える機能を追加する。

1. 詳細通知
   - サブスクリプションごとの複数通知
   - 通知時刻の指定
   - 無料お試し終了前の通知
   - 解約期限や契約更新期限の通知
2. 詳細分析
   - 月ごとの支出推移
   - 12か月予測
   - タグ別、カテゴリー別の支出内訳
   - 前月比、前年比
   - 支払いが集中する週や月の検出
3. エクスポート拡張
   - PDF レポート
   - JSON バックアップ
   - インポート前提のテンプレート CSV
4. 入力補助
   - よく使われるサービス名の候補
   - ロゴ、色、支払い周期の候補
   - タグ候補

### P2: 差別化につながる発展機能

中長期では、SubTrack の特徴に合う機能を追加する。

1. 解約支援メモ
   - 解約ページ URL
   - 解約手順メモ
   - 解約期限の管理
   - 解約代行ではなく、利用者自身の手続き支援に限定する
2. 家族・共有管理
   - 家族で確認したい支出の共有
   - 共有相手は閲覧だけ、編集可能など権限を分ける
3. 支出削減メモ
   - 使っていない候補の記録
   - 代替サービス候補のメモ
   - 年間で削減できそうな金額の試算
4. PWA 体験の強化
   - ホーム画面から次回支払いをすぐ確認
   - 通知許可やインストール状態に合わせた案内
   - オフライン時の確認体験を改善

## 有料化しない方がよい機能

次の機能は、無料プランにも残す方がよい。

1. 少数のサブスクリプション登録
2. 次回支払い日の確認
3. 基本的なカレンダー表示
4. 基本的な支出合計
5. 基本的な通知
6. アカウント、課金、解約に関する設定確認

これらを強く制限すると、初回利用者が価値を理解する前に離脱しやすい。
Premium では、基本機能を奪うのではなく、管理量が増えたときの手間を減らす方向で差を付ける。

## 注意点

金融機関や家計簿サービスとの自動連携は、初期の Premium 中核にしない。
外部 API、認可、セキュリティ、利用規約、個人情報保護の負荷が大きい。
SubTrack は、まず利用者が自分で登録する前提の安全な管理体験を強みにする。

広告非表示は、実際に広告を表示する場合だけ Premium 機能として扱う。
広告がない状態で「広告非表示」を主要訴求にすると、利用者に分かりにくい。

画像登録やロゴ管理は、保存先、容量、著作権、削除時の扱いを決めてから提供する。
単なる装飾ではなく、一覧で見つけやすくするための機能として説明する。

## 参考にした外部傾向

競合・近接サービスでは、無料枠で基本の記録や確認を提供し、有料枠で上限解除、詳細分析、通知、同期、エクスポート、カスタマイズを提供する構成が多い。

- Rocket Money は、無料で基本的なサブスクリプション管理や請求リマインダーを提供し、Premium で解約支援、詳細な管理、エクスポート、共有などを提供している。
- SubSense は、無料枠に登録件数の上限を置き、Premium で無制限登録、詳細分析、CSV / PDF エクスポート、同期、テーマ、優先サポートを提供している。
- Subsee は、銀行ログインを求めない手動管理、無料お試し終了、契約の解約期限、支出チャート、買い切り選択肢を訴求している。

## 実装メモ

契約状態の判定は、現在 `src/lib/server/plan.ts` で整理されている。
買い切り権限は `premium_lifetime` の有効な権限として扱われる。

サブスクリプション登録数の制限は、`src/routes/(storeFront)/subscriptions/+page.server.ts` の登録処理で判定されている。
CSV エクスポートは、`src/routes/(storeFront)/subscriptions/export/+server.ts` で Premium を必須にしている。

価格データは `scripts/stripe-products.json` に定義されている。
月額、年額、買い切りの表示を変える場合は、購入画面、FAQ、利用規約、特定商取引法に基づく表記、オンボーディングを同時に確認する。
