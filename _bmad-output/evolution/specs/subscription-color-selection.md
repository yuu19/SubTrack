# サブスクカラー選択と表示統一 仕様書

## Change Summary
サブスクの作成・編集フローにカラー選択を追加し、保存された色をカレンダーと分析画面の表示色として再利用する。変更は既存カレンダーパレットの 6 色プリセットに限定し、任意の色入力や大幅なレイアウト変更は行わない。既存データに対しては後方互換フォールバックを残し、段階的に新フィールドへ移行する。

## Before
- 追加モーダルと編集モーダルに色の入力項目がない。
- `tracked_subscription` は表示色を保持していない。
- カレンダー画面はサブスクの並び順に応じた固定ローテーションでイベント色を決めている。
- 分析画面は `--chart-1` から `--chart-5` の固定パレットを順番に割り当てている。
- オフライン追加 payload には色が含まれていない。

## After

### カラーモデル
- サブスクカラーは以下の 6 色キーに限定する。
  - `blue`
  - `green`
  - `red`
  - `yellow`
  - `purple`
  - `orange`
- カラーモデルは既存カレンダーで使っている色セットを再利用する。
- 任意の hex 入力、カスタムカラーピッカー、テーマ単位の色編集は今回の対象外とする。

### データ仕様
- `tracked_subscription` に `color` フィールドを追加する。
- 新規作成時は必ず `color` を保存する。
- 既存レコードは `color` が未設定でも表示可能にする。
- 色未設定の既存レコードは UI 上でフォールバックを使い、編集して再保存した時点で選択色を持つ。
- オフライン用 `SubscriptionPayload` と `SubscriptionRecord` にも `color` を追加する。

### フォーム仕様
- サブスク追加モーダルと編集モーダルにカラー選択 UI を追加する。
- カラー選択 UI は 6 色の丸型スウォッチを横並びまたは折り返しで表示する。
- 新規追加時の初期値は `blue` とする。
- 編集時は保存済みの `color` を初期表示し、未設定データは `blue` を仮表示する。
- 選択中の色はリングまたは枠線で明確に示す。
- カラー項目はサービス識別情報に近い位置に置き、サービス名の直後、周期の前に配置する。

### カレンダー表示仕様
- `/calendar` のイベント生成は、インデックスベースの色ローテーションではなく、各サブスクの `color` を優先して使う。
- `color` が未設定の既存サブスクのみ、現在のローテーションフォールバックを維持する。
- 日付セル内のイベントチップ背景色に保存色を使う。
- イベント詳細モーダルでは、各行に小さな色インジケータを表示し、一覧上でもどの色のサブスクか判別できるようにする。

### 分析表示仕様
- `/analysis` のチャートセグメント色と内訳リストのスウォッチは、サブスク由来の色を使う。
- 現在の金額集計ルール、月額換算・年額換算ルール、サービス名でのグルーピングは維持する。
- 同一 `serviceName` が複数件あり、色が混在する場合は、作成日時降順で見た最初の「色設定済み」レコードの色をそのサービスグループの代表色とする。
- 同一 `serviceName` の全件で色未設定の場合のみ、既存のチャートフォールバック色を使う。
- これにより、既存の分析ロジックを大きく崩さずに色の一貫性を導入する。

## Components

### New Components
- なし
- 今回は既存のカレンダーカラーパターンを流用し、専用の新コンポーネントを増やさずに実装する方針とする

### Modified Components
- `subscriptionSchema`
  - `color` フィールドを追加し、許可する値を 6 色キーに限定する
- `AddSubscription`
  - カラー選択 UI を追加し、保存時に `color` を送る
- `EditSubscription`
  - 現在色の表示と更新を可能にする
- `tracked_subscription` schema
  - 色カラムを追加する
- `payloadFromFormData` / オフライン保存処理
  - 色を payload とローカル保存に含める
- `/calendar`
  - イベント生成時に保存色を優先利用する
- `CalendarGrid`
  - イベント描画で渡された色をそのまま使う
- `EventDetailModal`
  - 明細行に色インジケータを追加する
- `buildSubscriptionAnalytics`
  - 集計結果に代表色を持たせる
- `/analysis`
  - 固定チャートパレット優先ではなく、集計結果の色を描画に使う

### Removed Components
- なし

### Unchanged Components
- 周期、金額、初回支払日、通知日数、タグの入力仕様
- カレンダーの日付計算と支払日算出ロジック
- 分析画面の月額換算・年額換算ルール
- 分析画面のサービス名ベースのグルーピング仕様
- ナビゲーション構造と画面導線

## Responsive Behavior
- モバイルではカラースウォッチを 2 行まで自然折り返しできるようにする。
- スウォッチは既存タグ削除ボタンと同等以上のタップしやすさを確保する。
- デスクトップでは 1 行表示を優先し、フォーム密度を大きく変えない。
- カレンダーと分析画面は既存レイアウトを維持し、色の差し替えだけで構造変更は行わない。

## Acceptance Criteria
- 追加モーダルで色を選択して保存すると、保存データに色が含まれる。
- 編集モーダルで現在色が表示され、別色へ変更して保存できる。
- カレンダーの日付セル内イベントは、保存色がある場合その色で表示される。
- カレンダー詳細モーダルでも各イベントの色を識別できる。
- 分析画面のドーナツチャートと内訳リストは、保存色または定義済みフォールバック色を使う。
- 同一サービス名の複数サブスクがある場合でも、分析の集計単位は従来どおりサービス名ベースのまま維持される。
- 色未設定の既存データは、追加の手動移行なしでもカレンダーと分析で表示できる。
- オフライン追加後に同期しても色が失われない。

## Open Edge Cases
- 同一サービス名で意図的に異なる色を設定した場合、分析画面は代表色 1 色のみを表示する。
- 今回は代表色ルールを導入し、サービス単位で複数色を混在表示する仕様には拡張しない。
- 将来的に「サービス単位の色統一」や「カスタム色入力」が必要なら別改善サイクルで扱う。
