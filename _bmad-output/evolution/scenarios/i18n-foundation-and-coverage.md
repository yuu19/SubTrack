# 共通UI向け i18n 基盤統一と翻訳欠落解消

## Target
ユーザー向け共通 UI に残っている未翻訳文言と、翻訳資産の分散を整理し、`ja` / `en` の切り替え時に主要導線で一貫した言語表示を成立させる。目的は、アプリ全体の i18n を「部分的に対応済み」から「運用可能な土台がある状態」へ引き上げること。

## Current State
- ストアフロント主要画面の多くは Paraglide を使っているが、共通 UI や一部静的ページには生文字列が残っている。
- `messages/ja.json` と `messages/en.json` のキー数に差があり、タグフィルタ関連の英語キーが欠落している。
- `src/lib/locale.ts` や各コンポーネント内の `locale === 'en' ? ... : ...` 分岐、ページローカル copy object が混在しており、翻訳の source of truth が一元化されていない。
- モバイルナビ、エラーページ、Google 認証ボタン、リダイレクト文言など、ユーザーが頻繁に触れる共通導線でも英語固定または個別分岐が残っている。
- 言語切り替えは設定画面から可能だが、切り替え後に共通導線の文言品質が揃う保証が弱い。

## Desired State
- ユーザー向け共通 UI の主要文言は Paraglide で管理され、`ja` / `en` で一貫して切り替わる。
- 既存の不足キーを補い、翻訳欠落による表示崩れや fallback 不整合を解消する。
- helper やコンポーネントに散っている locale ternary 文言のうち、ユーザー表示に関わるものは翻訳資産へ寄せる。
- 設定画面で言語を切り替えたあと、少なくともホーム、サブスク管理、分析、カレンダー、共通ナビ、基本エラー導線で言語が揃う。
- このサイクルでは「共通 UI と翻訳資産の整理」を優先し、法務本文の完全英訳や管理画面全体の多言語化は次の改善候補として切り分ける。

## User Journey
1. ユーザーがアプリを開き、ホーム、サブスク管理、分析、カレンダー、設定などの主要画面を移動する。
2. ユーザーが設定画面で言語を `ja` / `en` に切り替える。
3. 切り替え後、モバイルナビや共通ボタン、補助メッセージ、空状態、エラー導線などの共通 UI が選択ロケールで表示される。
4. ユーザーがタグフィルタや Google ログイン導線などを使っても、未翻訳キーや英語固定文言に遭遇しない。
5. 開発側は、今後の翻訳追加時に Paraglide を中心に追える構成になり、監査しやすくなる。

## Success Criteria
- `messages/en.json` に不足している `subscription_tag_filter_*` キーが追加され、購読一覧画面で欠落が起きない。
- `MobileBottomNav`, `GoogleAuthButton`, `+error.svelte`, `me/personal-info` などの共通導線で、固定文言がロケール対応される。
- カレンダー系や helper 内のユーザー向け locale ternary 文言のうち、今回対象に含めたものが翻訳資産へ寄せられる。
- 設定画面から言語切り替えを行った際、主要なユーザー向け共通 UI が `ja` / `en` で一貫する。
- DB スキーマや API 契約を変更せずに達成できる。

## Scope
- Pages/views:
  - `/`
  - `/subscriptions`
  - `/analysis`
  - `/calendar`
  - `/me/settings`
  - 共通エラー画面
- Components:
  - `MobileBottomNav`
  - `GoogleAuthButton`
  - `Header` の言語関連導線
  - カレンダー共通コンポーネントのユーザー向け文言
  - locale helper にある表示文言
- Data changes:
  - なし
  - 翻訳メッセージ定義と UI 文言参照方法の整理のみ
- Risk level:
  - Medium
  - 理由: データモデル変更はないが、複数の共通コンポーネントと翻訳参照経路を横断して調整する必要があるため
- Out of scope:
  - 管理画面全体の多言語化
  - 利用規約 / プライバシーポリシー本文の英語原文整備
  - locale 別サンプルデータ seed の見直し
