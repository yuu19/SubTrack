# サブスクカラー選択と表示統一

## Target
サブスクの作成・編集時にユーザーが色を選べるようにし、その選択色をカレンダー表示と分析表示に一貫して反映する。目的は、サービスごとの識別性を上げ、一覧、日付ビュー、分析ビューの間で同じサブスクを視覚的に追いやすくすること。

## Current State
- サブスク追加モーダルと編集モーダルにはカラー選択項目がない。
- カレンダー画面では、サブスクの保存色ではなく、表示順ベースの固定ローテーションで色が割り当てられている。
- 分析画面では、ドーナツチャートと内訳リストに固定チャートパレットが使われており、サブスクごとの意味のある色にはなっていない。
- そのため、同じサービスでも画面ごとに色の意味が一致せず、ユーザーが色を手がかりに追跡できない。

## Desired State
- サブスク追加モーダルと編集モーダルで、既存カレンダーと同じ 6 色プリセットから色を選べる。
- 新規保存時は選択した色がサブスクデータに保存される。
- 既存サブスクは色未設定でも表示でき、未設定時のみ後方互換フォールバックを使う。
- カレンダー画面では、各支払いイベントがそのサブスクの保存色で表示される。
- 分析画面では、ドーナツセグメントと内訳スウォッチにサブスク由来の色が使われる。

## User Journey
1. ユーザーが `/subscriptions` からサブスク追加モーダル、または編集モーダルを開く。
2. ユーザーがサービス名、周期、金額、初回支払日などと並んでカラー項目を確認する。
3. ユーザーが 6 色プリセットから 1 色を選んで保存する。
4. 保存後、`/calendar` では該当サブスクの支払いイベントが選択色で表示される。
5. `/analysis` では該当サブスクを含む内訳とチャートに同系統の色が使われる。
6. 色未設定の既存データは表示を壊さず、従来のフォールバック色で継続表示される。

## Success Criteria
- 新規作成時に色を選択して保存できる。
- 既存サブスクの編集時に現在色を確認・変更できる。
- カレンダーのイベントチップが保存色を使う。
- 分析画面のドーナツセグメントと内訳スウォッチが保存色を使う。
- 色未設定の既存サブスクでもカレンダーと分析が崩れず表示される。
- オフライン作成フローでも色が payload に含まれ、同期時に失われない。

## Scope
- Pages/views:
  - サブスク追加モーダル
  - サブスク編集モーダル
  - `/calendar`
  - `/analysis`
- Components:
  - `AddSubscription`
  - `EditSubscription`
  - カラー選択 UI
  - `CalendarGrid`
  - `EventDetailModal`
  - `DonutChart` 利用側
- Data changes:
  - `tracked_subscription` に色フィールドを追加
  - バリデーションスキーマ、サーバー actions、分析集計、オフライン payload に色を通す
- Risk level:
  - Medium
  - 理由: UI 変更に加えて、DB スキーマ、集計ロジック、オフライン同期経路に変更が入るため
