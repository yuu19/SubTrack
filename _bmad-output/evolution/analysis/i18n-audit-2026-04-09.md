# アプリ全体 i18n 棚卸し分析

## 対象
- SubTrack 全体の国際化対応状況
- 対象ロケール: `ja`, `en`
- 分析日: 2026-04-09

## Product Snapshot

### 現在の構成
- アプリは SvelteKit + Paraglide を使った多言語基盤をすでに持っている。
- ロケール定義は [project.inlang/settings.json](/home/yusuke/SubTrack/project.inlang/settings.json) で `ja` / `en` の 2 言語。
- サーバ側では [src/hooks.server.ts](/home/yusuke/SubTrack/src/hooks.server.ts) で Paraglide middleware とユーザー設定由来の locale cookie 上書きを行っている。
- ユーザー設定画面では [src/routes/(storeFront)/me/settings/+page.svelte](/home/yusuke/SubTrack/src/routes/(storeFront)/me/settings/+page.svelte) から [src/lib/components/LanguageSwitcher.svelte](/home/yusuke/SubTrack/src/lib/components/LanguageSwitcher.svelte) を利用できる。
- ストアフロント主要画面の多くは `m.*` を使っており、Paraglide ベースで翻訳されている。

### 既存の i18n 実装パターン
- Paraglide メッセージ: `messages/*.json` と `m.*`
- ロケールヘルパー内の直接分岐: [src/lib/locale.ts](/home/yusuke/SubTrack/src/lib/locale.ts)
- コンポーネント内の `locale === 'en' ? ... : ...` 分岐
- ページローカルの `Record<'ja' | 'en', ...>` copy オブジェクト
- 法務文書 markdown を直接読み込む構成

### 現状評価
- 「多言語対応の導入」は完了している。
- ただし「翻訳の一元管理」「表示の網羅性」「運用しやすさ」は未整備で、アプリ全体としてはまだ監査・統合作業が必要。

## 主な観測結果

### 1. 多言語の source of truth が分散している
- Paraglide 以外に、[src/lib/locale.ts](/home/yusuke/SubTrack/src/lib/locale.ts)、[src/lib/content/site-content.ts](/home/yusuke/SubTrack/src/lib/content/site-content.ts)、[src/routes/(storeFront)/push/+page.svelte](/home/yusuke/SubTrack/src/routes/(storeFront)/push/+page.svelte)、[src/lib/components/onboarding/OnboardingDialog.svelte](/home/yusuke/SubTrack/src/lib/components/onboarding/OnboardingDialog.svelte) などで独自に文言を保持している。
- 結果として、「翻訳キーを追加すれば全体が揃う」状態になっておらず、漏れが発生しやすい。

### 2. 英語・日本語のカバレッジにズレがある
- `messages/ja.json` には存在し `messages/en.json` に存在しないキーが 3 件ある。
- 対象キー:
  - `subscription_tag_filter_active`
  - `subscription_tag_filter_clear`
  - `subscription_tag_filter_empty`
- これらは購読一覧画面で使われており、英語環境での欠落リスクがある。

### 3. 法務ページは見出しだけ英語化され、中身は日本語固定
- [src/routes/(storeFront)/terms/+page.svelte](/home/yusuke/SubTrack/src/routes/(storeFront)/terms/+page.svelte) と [src/routes/(storeFront)/privacy/+page.svelte](/home/yusuke/SubTrack/src/routes/(storeFront)/privacy/+page.svelte) は locale に応じて head/title を切り替えている。
- しかし本文は [src/lib/content/site-content.ts](/home/yusuke/SubTrack/src/lib/content/site-content.ts) で `docs/利用規約.md` と `docs/プライバシーポリシー.md` の日本語 markdown だけを読み込んでいる。
- そのため、英語 UI でも法務本文は日本語のままになる。

### 4. 管理画面は英語固定で Paraglide 未適用
- [src/routes/admin/+page.svelte](/home/yusuke/SubTrack/src/routes/admin/+page.svelte)
- [src/routes/admin/users/+page.svelte](/home/yusuke/SubTrack/src/routes/admin/users/+page.svelte)
- 管理画面は日本語/英語の切り替え対象外になっており、アプリ全体の i18n 完了状態とは言えない。

### 5. 共通導線に未翻訳の生文字列が残っている
- [src/lib/components/MobileBottomNav.svelte](/home/yusuke/SubTrack/src/lib/components/MobileBottomNav.svelte) は `Home`, `Subscriptions`, `Analytics`, `Calendar`, `Settings` を固定文字列で保持している。
- [src/routes/+error.svelte](/home/yusuke/SubTrack/src/routes/+error.svelte) は完全に英語固定。
- [src/lib/components/GoogleAuthButton.svelte](/home/yusuke/SubTrack/src/lib/components/GoogleAuthButton.svelte) もデフォルトラベルとエラー文言が英語固定。
- [src/routes/(storeFront)/me/personal-info/+page.svelte](/home/yusuke/SubTrack/src/routes/(storeFront)/me/personal-info/+page.svelte) は `Redirecting to settings...` 固定。

### 6. locale 分岐が helper / component に散っている
- [src/lib/locale.ts](/home/yusuke/SubTrack/src/lib/locale.ts) に周期名、通知日ラベル、契約ステータスなどの文言が直接埋め込まれている。
- [src/lib/components/calendar/CalendarHeader.svelte](/home/yusuke/SubTrack/src/lib/components/calendar/CalendarHeader.svelte) と [src/lib/components/calendar/EventDetailModal.svelte](/home/yusuke/SubTrack/src/lib/components/calendar/EventDetailModal.svelte) にも locale ternary の UI 文言がある。
- 翻訳資産が JSON ではなく実装コード側に分散し、監査や翻訳レビューがしづらい。

### 7. 言語切り替え UI の到達性が限定的
- 設定画面では切り替え可能だが、[src/lib/components/Header.svelte](/home/yusuke/SubTrack/src/lib/components/Header.svelte) では `LanguageSwitcher` がコメントアウトされている。
- 初回訪問時や法務ページ閲覧時に言語変更へ辿りにくい。

### 8. デフォルトデータと運用文言に日本語依存が残っている
- [src/routes/(storeFront)/+layout.server.ts](/home/yusuke/SubTrack/src/routes/(storeFront)/+layout.server.ts) のサンプルデータはタグが `動画`, `エンタメ`, `音楽`, `仕事`, `ツール` で固定。
- 英語ユーザーでも seeded data に日本語タグが入るため、初期体験の言語一貫性を壊す。

### 9. WDS 設定と実アプリ状態にズレがある
- [_bmad/wds/config.yaml](/home/yusuke/SubTrack/_bmad/wds/config.yaml) では `product_languages` が `en` のみ。
- 実アプリは `ja/en` を運用しているため、設計資産の前提が現状と一致していない。

## Root Cause
- 国際化の導入は機能単位で進み、横断的な設計原則がまだ確立されていない。
- その結果、「Paraglide を使う場所」と「ローカル copy や ternary で済ませる場所」が混在している。
- 法務文書・管理画面・サンプルデータのような周辺領域が監査対象から外れ、翻訳カバレッジが UI 中心で止まっている。

## Improvement Targets
1. i18n source of truth の統一  
Impact: High / Effort: Medium / Learning: High  
Paraglide 外に散っている copy を集約し、翻訳追加と監査を一か所で回せるようにする。

2. 翻訳カバレッジ欠落の解消  
Impact: High / Effort: Medium / Learning: Medium  
管理画面、エラーページ、モバイルナビ、Google 認証ボタン、タグフィルタ関連キーを翻訳対象へ揃える。

3. 法務・静的コンテンツのロケール整合  
Impact: High / Effort: Medium / Learning: Medium  
FAQ は両言語化済みだが、利用規約/プライバシー本文は日本語固定のため、英語 UI と整合しない。

4. 言語切り替え導線の改善  
Impact: Medium / Effort: Low / Learning: Medium  
設定画面以外でもロケール変更へ到達できるようにする。

5. locale 依存初期データと運用文言の見直し  
Impact: Medium / Effort: Low / Learning: Medium  
sample data、helper 文言、サーバ由来の固定文字列を監査する。

## Selected Target
- **アプリ全体 i18n 整備の土台づくり**
- 理由:
  - 今は個別画面を直しても、翻訳資産の分散により再発しやすい。
  - 法務・管理画面・共通 UI を含めた全体監査が先に必要。
  - この棚卸しを終えると、以降の改善を「翻訳キー追加」「coverage 修正」「法務文書差し替え」に分解しやすくなる。

## Success Criteria
- すべてのユーザー向け画面・管理画面・法務ページについて、`ja/en` の対応状態を分類できている。
- Paraglide 外の copy 保持箇所を一覧化できている。
- 翻訳欠落キーと日本語/英語固定の UI を特定できている。
- 次の Scope Improvement で、1サイクルに収まる改善単位へ分解できる。
